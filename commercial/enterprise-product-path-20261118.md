# KAHRELUM enterprise assurance product path
Date: 2026-11-18
Status: INTERNAL PRODUCT POSITIONING; NOT A SOFTWARE RELEASE

## Market thesis
One evidence-to-decision review framework can support multiple vertical examples, without implying one codebase currently powers a live evaluation API or continuous governance SaaS. Commercial priority: sell the review already available, generate credible externally controlled evaluation evidence, then prove the repeatable product interface before selling production monitoring.

## CURRENT: operator-assisted retrospective review
Publicly available: $750 Fit Check (three authorized, de-identified closed cases in one workflow), $2,500 Founding Pilot (up to ten cases, one workflow). Written findings, negative cases and limitations remain explicit. Public inquiry prepares an email; it is not an upload portal. Existing private contractual quotes are handled privately and are not public pricing.

## PROPOSED: AI vendor evaluation as expansion
Design candidate batch case ingestion, frozen source cutoff, policy context, evaluative rubric, source-linked counterevidence, reviewer sign-off and versioned JSON audit record. Develop a real contract, fixtures, tests and security controls before calling this an API. Pilot proposals over existing fixed-scope limits require independent SOW and approval; do not claim $15,000 trial sales or committed terms.

## FUTURE: enterprise governance
Extend the same schema or audit record to event/decision ledgers, policy versions, approval state and independent challenge history. Continuous production monitoring, integrations, SSO, multitenancy, audit retention and data residency are NOT currently validated, live or offered as SaaS. Avoid implying statutory compliance or ISO/SOC2 certification.

## The shared schema v0.1
See /data/assurance/synthetic-reviews-v0.1.json for five invented case records. Schema fields intentionally align across sectors: case_id, sector_id, workflow, decision_at_cutoff, source_snapshot, policy_at_cutoff, gap_found, counterargument, review_disposition, required_next_evidence, limitations. JSON publication alone does not make an executable evaluation API.

## Evidence gates for advancing product status
1. Buyer-controlled proof of repeatability and assessment value on consented cases.
2. Versioned schema with explicit unknowns; test suite and sample artifacts.
3. Security model, privacy controls and jurisdiction/vendor eligibility confirmed.
4. API conformance, authorization tests, rate limits, observability, uptime and cost models proven before release claims.
5. Live governance only after production integration and human-approved legal, security and commercial review.
