# KAHRELUM OS — Intelligence Pipeline

KAHRELUM runs as a **pipeline of differentiated analytical responsibilities**, not one model pretending to discover, verify, red-team, decide, and audit itself simultaneously.

## Canonical sequence

```
ROUTER
  → SCOUT
  → SOURCEGRID
  → K-ALIGN
  → IPR
  → BLACKGLASS-I
  → CRF
  → COMMAND
  → BLACKGLASS-II
  → RECORD LOCK
```

AAIK governs the cycle as an independent evidence / instability / exposure governor.

## Operational responsibilities

| Stage | Primary job | Must not become |
| --- | --- | --- |
| **ROUTER** | Select depth, mode, and control requirements | DEEP-always ceremonial routing |
| **SCOUT** | Discover signals, evidence, hypotheses, dependencies | Approval authority |
| **SOURCEGRID** | Map provenance, independence, tiers, freshness, contradictions | Link-count voting |
| **K-ALIGN** | Reconcile dates, windows, objects, definitions, denominators, status | “Basically the same” reasoning |
| **IPR** | Identify variables capable of changing the distribution next | Generic recap |
| **BLACKGLASS-I** | Attack the thesis and search for falsifiers | Thesis rescue |
| **CRF** | Build coherent probabilities / scenarios | Uncalibrated confidence language |
| **COMMAND** | Select action state and communicate the BLUF | Override of mission-completion failures |
| **BLACKGLASS-II** | Attack the chosen action, exposure, timing, and implementation | Rubber-stamp of COMMAND |
| **RECORD LOCK** | Freeze evidence state, decision, uncertainty, and resolution trail | Hindsight rewrite |

## MCRI in the pipeline

MCRI — Mission Contract Release Interlock — sits across the pipeline.

Before retrieval, explicit requirements are decomposed into atomic mission requirements. The pipeline may not self-certify PASS while an active mandatory atom is omitted, substituted, unresolved, or unsupported.

A negative answer can satisfy an atom only when the relevant negative closure is actually established.

## Cognitive roles

- **Luna** — hypothesis expansion / weak signals / second-order effects
- **Terra** — evidence verification / provenance / realism / constraints
- **Sol** — synthesis / probability / action / uncertainty
- **AAIK** — evidence / instability / exposure governor

## Commercial / opportunity overlay

For commercial-intelligence opportunity triage, a compact overlay remains useful:

```
SCOUT (find)
→ BLACKGLASS (attack)
→ independent verify
→ KAHRELUM decide
```

That overlay does not replace the canonical OS pipeline; it is a domain-specific compression of it.

## Decision states

`MONITOR | WAIT | REJECT | INVESTIGATE | HEDGE | TRADE | PUBLISH | ESCALATE | PREPARE`

Consequential actions remain subject to the human approval boundary.

## Core anti-failure rules

KAHRELUM is deliberately hostile to:

- source recycling presented as independent corroboration;
- absence of evidence presented as evidence of absence;
- window and denominator mismatches;
- substitute metrics answering a different question;
- legal or operational status collapse;
- silently dropped mission requirements;
- probability language masquerading as verification;
- hindsight rewriting of prior forecasts or decisions.

The objective is not merely to produce plausible analysis. It is to make analytical shortcuts, hidden substitutions, and mission incompleteness harder to pass unnoticed.
