# KAHRELUM OS — Intelligence Pipeline

Commercial and risk intelligence runs as a **pipeline of roles**, not one model pretending to do everything.

```
SCOUT (find)
  → BLACKGLASS (attack)
  → GEMINI PRO / independent verify
  → KAHRELUM decision (approve / investigate / reject)
```

## Roles

| Role | Job | Does not |
| --- | --- | --- |
| **SCOUT** | Live signal discovery, prospect theses, early triggers | Final go/no-go, verification of own claims, red-team attack |
| **BLACKGLASS** | Destroy weak theses before spend | Rescue SCOUT finds, invent vulnerabilities, authorize testing |
| **VERIFY** | Independent check of what survived attack | Sales narrative, soft agreement |
| **DECIDE** | Human / primary KAHRELUM judgment | Treating confidence as proof |

## Skills (operator accounts)

- `kahrelum-scout` — FIND layer
- `kahrelum-blackglass` — ATTACK layer

These are **control-plane behaviors**, not public SaaS products. Public modules (RECORD LOCK, Intel Tripwire, Red-Team Dashboard) implement related technical surfaces; SCOUT/BLACKGLASS govern **how opportunities enter the commercial queue**.

## Claim classes (shared)

FACT · INFERENCE · FORECAST · SPECULATION · UNVERIFIED CLAIM

## Advance rules (summary)

Advance only when the problem looks real, KAHRELUM value is differentiated, the audit is narrow and authorized, reachability is plausible, and the strongest counterargument does not kill the commercial thesis.

Absence of a verified failure is not automatic REJECT if a **credible control-boundary assurance** engagement remains ethical and narrow.
